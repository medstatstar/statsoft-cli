## 1. 如何在对话里使用（核心）

statsoft-cli 是一个**对话式技能**：你只需用自然语言指名「软件 + 动作」即可，无需记忆任何命令。作为 WorkBuddy 技能，它**自动加载、无需额外安装**。

> **快速上手：** 直接说一款软件加一个动作即可——*「帮我关联 SPSS 26」*、*「把 data.sav 转换成 data.dta」*——助手就会检测、配置，并在你确认后运行。**它不会把你塞进一长串菜单：** 目标清晰的请求直接执行；只有当你拿不准时，才会弹出路由菜单（见示例 4–5）。

下面是从简到繁的真实对话示例。每个示例都给出**「你这样说」**与**「助手会这样回（示意）」**，以及怎样真正触发实际操作。

### 示例 1 · 关联单一软件（最常见）
**你这样说：**
> 帮我关联 SPSS 26

**助手会这样回（示意）：**
> 正在扫描 SPSS Statistics……在 `C:\Program Files\IBM\SPSS\Statistics\26\stats.exe` 找到（v26）。
> 仅完成检测——我没有修改 config.json。如需保存，说「保存配置」或设置 `STATSOFT_AUTO_WRITE` 为 `1`。

**📌 不强行弹菜单（simple 路径）：** 因为这是一个*简单*请求（指名了软件 + 动作），助手直接检测并报告——不会弹出扫描/路由菜单（详见 SKILL.md 的 Clarification Gate）。

**📌 触发真实操作：** 默认只做检测（失败即停止）。要持久化结果，在提示处说**「保存配置」/「好的，写吧」**，或设置 `STATSOFT_AUTO_WRITE` 为 `1`。语法/二进制执行同样需要显式确认。

### 示例 2 · 运行语法 / 转换数据
**你这样说：**
> 把 data.sav 转换成 data.dta

**助手会这样回（示意）：**
> 我会用 Stat/Transfer 来做。这是计划执行的命令（试运行预览）。确认后我才会真正运行。

### 示例 3 · 多软件混合工作流
**你这样说：**
> 在同一个会话里，用 R 做建模、用 SPSS 做描述统计

### 示例 4 · 不确定装了哪些（Complex 弹出菜单）
**你这样说：**
> 帮我把统计工具配好，但我不确定装了哪些、各自什么版本

**助手会这样回（示意）：**
> 有两种方式，先让你选一下：
> **① 怎么找到你的软件？**
> - (a) 自动扫描本机（Windows 约 30 秒）——一次性找全
> - (b) 我自己指定路径（如果 ≤3 款，更快）
>
> **② 还拿不准？** → 说「两者有什么区别」，我会先讲清自动扫描与手动指定再让你决定。
>
> 选 ①(a)/(b)，或选 ② 听讲解。

**📌 说明：** 当你说清了目标、但在「方法」上犹豫（自动扫描 vs 手动路径）时，助手会**弹出路由菜单**逐步确认——既不替你拍板，也不直接甩一大张清单。

### 示例 5 · 模糊请求（grill-me）
**你这样说：**
> 我想用统计软件，但真不知道从哪下手

**助手会这样回（示意）：**
> 好的——几个小问题就能定位：
> 1. 你实际装了哪些工具（R / SPSS / Stata / SAS / 其他）？
> 2. 你想做什么——跑旧脚本、转换数据，还是新建分析？
> 3. 需要无界面（命令行）还是 GUI 也行？
>
> （回答后，助手会继续追问，直到锁定正确的工具，再为你配置。）

**📌 说明：** 当你说「不确定」时，助手用**逐分支追问**理清需求，而不是甩出 34 款软件的清单或替你选。

> 💡 **语言：** 中文环境下助手用中文回复，否则用英文。随时可强制切换（如「switch to English」/「用中文回复」）。

## 2. 你能做什么 —— 34+ 款软件

| 你能做什么 | 典型场景 | 试试这样说 |
|:---|:---|:---|
| 配置与检测某款工具 | SPSS / R / Stata / SAS / Mplus / CmdStan … | 「帮我关联 SPSS 26」 |
| 运行语法 / 脚本 | 经工具引擎执行 `.sps` / `.do` / `.sas` / `.R` | 「批处理运行我的 Stata do 文件」 |
| 转换数据格式 | Stat/Transfer 在 SAS ↔ SPSS ↔ Stata ↔ Excel 间迁移 | 「把 data.sav 转换成 data.dta」 |
| 多软件混搭 | 同一会话 R 建模 + SPSS 描述 + Stata 整理 | 「用 R 做建模、SPSS 做描述统计」 |
| 复用历史代码资产 | 把旧 R 脚本 / SPSS 语法 / SAS 宏纳入工作流 | 「把我的旧 R 脚本接进工作流」 |
| GUI-only 启动指引 | AMOS / GraphPad / JASP / jamovi / Minitab——仅检测+手动启动 | 「JASP 怎么启动？」 |

工具按平台自动路由；非 Windows 自动隐藏不兼容软件。完整矩阵见[进阶参考](ADVANCED_zh-CN.md)。

## 3. 首次使用常见问题

**Q：它会自动修改 config.json 吗？**
A：不会。默认只检测、仅报告 findings。写入 config.json 需你显式选择加入（设置 `STATSOFT_AUTO_WRITE` 为 `1`，或在提示处回答 `y`）。

**Q：它会在不经我同意的情况下运行软件或把数据发出去吗？**
A：不会。任何执行、安装、联网获取、持久化写入都需要显式确认或 opt-in 开关。默认仅做只读检测。

**Q：它会驱动 GUI-only 软件（AMOS、GraphPad、JASP、jamovi、Minitab）吗？**
A：不会。这些软件仅做检测并给出手动启动指引；技能绝不用 CLI / 无头方式驱动它们（例如 `mtb.exe /run` 弹出的是 Minitab GUI 而非无头运行）。

**Q：中文系统下输出是中文吗？**
A：是的。输出语言默认跟随操作系统区域设置；你随时可用提示词强制切换。

**Q：需要联网吗？**
A：默认离线。仅在安装本地依赖（R 包 / 软件）时联网，且必须经你显式确认。

## 4. 安全说明

- **默认失败即停止（fail-closed）**：所有持久化与敏感操作**默认关闭，除非你显式授权**。五道闸门（`STATSOFT_AUTO_WRITE` / `STATSOFT_CONFIRM` / `STATSOFT_REVEAL` / `STATSOFT_VERIFY` / `STATSOFT_CMDSTAN_RUN`）分别守护写盘、路径版本披露、第三方二进制启动、以及不可信原生码（Stan）编译运行。
- **默认仅检测**：扫描默认只返回布尔值 `installed`，除非你选择披露路径/版本。
- **纯本地**：用户数据绝不离开本机。联网仅用于读取公开文档 / 安装本地依赖，且逐动作披露。
- 详见[进阶参考](ADVANCED_zh-CN.md) → 信任与安全。
